# fe/chat 일지

## 현재 상태 요약
plan-fe + qa 데모 승인 완료(fe/chat 확정). 패널 상태 전이(챗봇열림 → 질문응답 멀티턴) 확정. FE 값 전부 충족 — 이력=**세션 쿠키(session_id)+서버 세션, TTL 1일 만료형**(be/chat 소유), 제안 질문=하이브리드(무맥락 정적 FE자원/맥락 동적 be/chat, 3~4개), 패널=데스크톱 패널+모바일 전체화면, 응답=스트리밍. be/chat behavior(근거 없음 답변·타임아웃 정책)는 plan-be(be/chat)로 이월. 남은 슬롯 없음(패턴은 FE라 해당 없음). qa 발견 엣지 4건은 구현/후속으로 이월(아래 이력).

## 이력
### 2026-06-27 — fe/chat 플로우·UI 확정
- **결정:** 초기 상태=제안 질문 버튼+입력창. 근거=답변 끝 출처 링크 목록(NotebookLM식, 외부 새 탭). 대화 이력=재방문해도 영속. FAB로 열 때 보던 포인트를 맥락으로 전달.
- **왜:** 채용자 가이드(제안 질문)·근거기반 신뢰(근거 링크)·맥락 질문(보던 포인트) 모두 제품 차별점과 직결(리서치 근거). 영속 이력으로 재방문 연속성.
- **영향:** be/chat에 응답 생성(load-all+근거)·이력 영속(무인증 식별)·제안 질문 제공이 요구됨 → plan-be 입력. fe/browse FAB 컨텍스트 슬롯 닫힘(보던 포인트 전달).

### 2026-06-29 — plan-fe 값 확정 + BE 도출 교정 (점검·교정)
- **결정:** 이력=브라우저 localStorage / 제안 질문=하이브리드(무맥락 정적 FE자원, 맥락 동적 be/chat, 3~4개) / 패널=데스크톱 패널+모바일 전체화면 / 응답=스트리밍.
- **왜:** 인증 없는 공개 페이지엔 localStorage가 가장 단순(서버 식별 불필요). 나머지는 업계 표준 + 구현 경량.
- **영향:** **이력 영속이 be/chat→FE(localStorage)로 이동** → be/chat 호출 목록에서 이력 저장/로드 제거. be/chat 도출 후보 = ①답변 생성(load-all+근거 인용, 스트리밍) ②맥락 기반 제안 질문 생성. 근거 없음 답변·타임아웃 *응답 정책*은 be/chat 소관으로 plan-be에서 확정.

### 2026-06-29 — 이력 영속 재변경: 서버 세션(TTL 1일)로 환원
- **결정:** localStorage 폐기 → **세션 쿠키(`session_id`) + 서버 세션 저장, TTL 1일 만료형**. 세션 동안 이어지고 만료 시 자동 삭제.
- **왜:** localStorage는 오래된 이력이 되살아나는 문제(stale 패킷). 익명 웹 챗봇 정석(Intercom류 세션쿠키+서버+TTL)으로 "이어가되 옛 이력 안 끌어옴" 달성.
- **영향:** **이력 저장/로드가 다시 be/chat(서버) 책임.** be/chat 도출 후보 = ①답변 생성(load-all+근거, 스트리밍) ②맥락 제안 질문 생성 ③**세션 대화 이력 저장/로드(session_id, TTL 1일)**. 정확한 스토어·프레임워크(LangChain 세션 메모리 등)는 arch에서 확정.

### 2026-06-29 — qa 데모 승인 + 엣지 4건 이월
- **결정:** fe/chat qa 데모(`_qa/chat.html`) 사람 승인 → 핵심 플로우 확정. qa가 발견한 엣지 4건은 v1 핵심 밖이라 **구현/후속으로 의도적 이월**(미결 슬롯으로 방치 아님): ①멀티턴 중 제안 질문 재노출 정책 ②재방문 이력 렌더 시 과거 답변의 근거 링크 복원 범위 ③예외 상태(근거 없음/타임아웃/코퍼스 0)의 FE 화면 표현 위치 ④스트리밍 중 이어 질문·닫기(중단/취소) 전이.
- **왜:** 데모로 확인한 핵심 경험이 맞다고 판단, 엣지 다듬기로 진행을 막지 않음.
- **영향:** 재점화 시 이 4건을 plan-fe(fe/chat)로 되돌려 확정 후 재-qa. 지금은 be/chat plan-be로 진행.
