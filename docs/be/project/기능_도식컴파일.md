# 기능: 도식컴파일 *(v4 신설)*

*빌드/발행 시 1회, 프로젝트의 typst 도식 소스(`.typ`)를 SVG로 컴파일해 사이드카 애셋으로 저장하고 표지 `architectureDiagram`이 그 SVG를 가리키게 한다. 빌드타임 유틸 — 서빙 시엔 정적 SVG만 내보내고 컴파일하지 않는다.*

## 다루는 데이터
- [데이터.md](데이터.md)#아키텍처-도식-typstsvg--표지-종속 (`.typ` 소스 읽기 → `.svg` 애셋 쓰기)
- [데이터.md](데이터.md)#프로젝트index-표지 (`architectureDiagram` 채움 대상)

## 입력
- 프로젝트 1개(또는 전체)의 typst 도식 소스 사이드카.

## 처리
- 도식 소스(`.typ`)가 있는 프로젝트마다 **typst→SVG 컴파일** 후 사이드카 `.svg`에 기록, 표지 `architectureDiagram`을 그 경로로 설정.
- 소스 없으면 스킵(`architectureDiagram=null`).
- 산출 경로(확정): 소스 `wiki/<project>/architecture.typ` → 애셋 `wiki/<project>/architecture.svg`(데이터.md 사이드카 규칙). 컴파일 단위 = 프로젝트별 1개.

## 출력·변경
- 각 대상 프로젝트의 `.svg` 애셋 생성 + 표지 `architectureDiagram` 채워짐(빌드 시 1회). 이후 [프로젝트인덱스조회](기능_프로젝트인덱스조회.md)가 함께 반환, fe/browse가 임베드.
- 프로젝트 카탈로그·표지 조회 계약(6요소)은 불변 — 이 단계는 애셋 부가 생성.

## 예외·경계
- 컴파일 실패(typst 미설치·소스 문법 오류 등)(확정): 발행/빌드 스크립트가 **사람에게 프롬프트**한다 — "도식 비우고 발행할까요(architectureDiagram=null) / 중단할까요?". 발행은 로컬에서 사람이 직접 돌리는 플로우라 대화형 결정이 가능. 기본 제안 = 도식 비우고 진행(architecture 텍스트는 유효).
- 재빌드: 기존 `.svg` 덮어씀(최신 소스 반영) — 확정.
