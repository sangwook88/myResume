# be/point 일지

## 현재 상태 요약
fe/browse qa 매핑표에서 도출한 골격 + 사람 값 확정 완료(plan-be). 데이터(포폴포인트 frontmatter+9섹션 본문+Evidence 5종) + 기능 3개(추천목록·프로젝트별목록·단건조회). 비즈니스 값 전부 충족 — 추천=featured 우선+동점 최신순 상위3, 정렬=구현 기본, 발행=별도 명령(Evidence≥1+핵심섹션 1·3·5·9 검증), 비공개/없는 항목=랜딩 리다이렉트, 포맷=케밥/ISO/git range. 남은 슬롯은 패턴(TS/DM, arch)뿐.

## 이력
### 2026-06-29 — be/point 신설 (FE-first 도출)
- **결정:** decompose에서 프로젝트 표지를 be/project로 분리(SRP) → be/point는 개별 포폴 포인트(2계층)만 소유. fe/browse qa가 부르는 호출(추천목록·프로젝트별목록·단건)에서 기능 3개 도출, 데이터는 목차-설계 §5·§7 frontmatter+9섹션+Evidence로 역산.
- **왜:** 포인트와 프로젝트 표지는 각자 다른 데이터를 소유 → 단일 소유 규칙·세분할 granularity.
- **영향:** be/point는 말단(sink, depends 없음). be/project·be/chat이 be/point를 단방향 참조.

### 2026-06-29 — 값 확정 (사람 결정)
- **결정:** 추천=`featured` 태그 우선+동점 `updated` 최신순 상위 3 / 목록 정렬=구현 기본(임의) / 발행=별도 명령으로 draft→published, 게이트 검증=Evidence≥1+핵심 섹션(1·3·5·9) / 비공개·없는 id=랜딩 리다이렉트 / 부분 렌더=선택 섹션 비면 생략 / Evidence kind=commit·pr·swagger·file·link / 포맷=id·slug 케밥, updated ISO, commits git range.
- **왜:** 개인 포폴·로컬 구독 저작 모델이라 큐레이션·경량 게이트가 적합. 근거 강제(Evidence≥1)는 제품 차별점.
- **영향:** be/point 비즈니스 슬롯 전부 충족. 남은 건 arch의 패턴(TS/DM)뿐 → distill 가능.

### 2026-06-29 — arch 패턴 확정: TS
- **결정:** 패턴 = 트랜잭션 스크립트(TS). 스택 = Python/FastAPI, 콘텐츠는 git 마크다운을 Python이 파싱해 API 서빙.
- **왜:** 파일 파싱→DTO 조회 + 발행 게이트 검증은 얇은 절차적 규칙이라 도메인 모델 과설계.

### 2026-06-29 — distill 가지치기
- **결정:** Evidence kind 표 셀의 stale 표기(3종→enum 5종 참조)로 정제, 추천 입력의 자명한 메타 1줄 삭제, 단건조회 리다이렉트 중복(처리·예외)을 예외 1곳으로 통합.
- **왜:** 핵심 의미 보존하며 군더더기·중복·불일치 제거(slim-agent).
- **영향:** 의미 불변. be/project 문서는 이미 완결이라 변경 없음.
