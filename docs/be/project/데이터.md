# be/project 데이터 (M)

*이 도메인이 소유한 마스터 데이터. 파일 단위 = `wiki/<project>/index.md` 1개 = 프로젝트 표지 1개. 근거: [포폴-목차-설계.md §4](../../포폴-목차-설계.md).*

## 프로젝트(index 표지)
*프로젝트 1개의 카탈로그 메타. 목차-설계 §4의 1~5번(6번 포인트 목록은 be/point에서 파생 — 저장 안 함, §7.3).*

| 필드 | 타입 | 의미 | 값·범위 |
|---|---|---|---|
| slug | string(slug) | 프로젝트 식별자 (포인트의 `project`와 매칭) | 케밥 영문 slug (예 `shopping-mall`) |
| summary | string | 한 줄 요약(무엇을·왜·누구를 위해) | 자유 문자열, v1 강제 길이 제한 없음 |
| role | string | 나의 역할(기여 범위) | 자유 문자열 |
| period | string | 기간 | `YYYY.MM–YYYY.MM` (진행 중이면 `YYYY.MM–`) |
| teamSize | string | 팀 규모 | 자유 문자열 (예 `5명 (BE 3·FE 1·QA 1)`) |
| techStack | string[] | 기술 스택(언어/프레임워크/인프라) | 자유 문자열 배열, v1 고정 집합 없음 |
| architecture | string | 아키텍처 개요 | **텍스트/마크다운** (다이어그램 이미지는 뒤 버전) |
| highlights | string[] | 핵심 성과(임팩트 하이라이트) | 자유 문자열 배열, 강제 개수 제한 없음(권장 3) |

> 포폴 포인트 목록은 이 테이블에 저장하지 않는다 — [be/point 포인트목록조회](../point/기능_포인트목록조회.md)로 `slug` 기준 published 포인트를 스캔해 조립(목차-설계 §7.3).

## enum
*프로젝트 표지 자체에는 발행 status를 두지 않는다. published 포인트 0개인 프로젝트도 노출하되 카탈로그에서 후순위 배치 + 인덱스의 포인트 목록 슬롯은 숨긴다.*
