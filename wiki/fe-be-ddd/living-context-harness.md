## 제목·요약
도메인마다 `현재 상태 요약`을 그 도메인의 **누적된 맥락·학습**으로 살려 둔다. AI는 이 요약을 읽고 지금까지 쌓인 결정에 맞춰 동작한다 — 도메인에 "누적 학습"을 시키는 구조다. 이 요약이 낡은 레거시로 썩지 않도록, **하네스가 개발이 끝나면 요약 갱신을 무조건 강제**한다. AI가 스스로 만든 문서가 쌓여 환각을 부르는 문제를 규약으로 원천 차단한다.

## 배경
LLM 위키를 도메인 경계 그 자체로 삼는 이 프레임워크에서, 각 도메인 폴더는 계약(데이터·기능 / 플로우·표현)뿐 아니라 "지금 이 도메인이 어떤 상태인가"라는 맥락도 담는다. AI 에이전트는 콜드 스타트로 이 도메인에 들어와 일한다.

## 문제
AI 코딩의 고질병: 에이전트가 만든 문서·이력이 계속 쌓이고, 그 누적물이 곧 낡은 레거시가 되어 다음 에이전트가 그걸 읽고 환각을 일으키거나, 매번 사람이 손으로 갱신해야 한다. 맥락을 다 주자니 이력이 쌓여 오염되고, 안 주자니 도메인의 현재 상태를 몰라 헛짚는다.

## 고려한 옵션
| 옵션 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 이력·요약을 다 읽혀 맥락 제공 | 정보 풍부 | 누적 이력 = 레거시·토큰 폭발·환각 | X |
| 맥락 문서를 아예 안 둠 | 오염 없음 | 도메인 현재 상태 미인지 → 헛짚음 | X |
| 요약(읽음·갱신 강제) + 이력(쓰기 전용·안 읽음) 분리 | 항상 최신 맥락만 읽힘 / 이력은 사람 디버깅용으로 격리 | 하네스 규약을 지켜야 유효 | O |

## 결정과 근거
읽는 것과 쌓는 것을 분리했다. **`현재 상태 요약`**은 도메인의 누적 학습으로, AI가 읽고 그에 맞춰 동작한다. **`일지.md`**는 결정 이력 로그로 **쓰기 전용 — AI는 절대 읽지 않는다**("쌓인 이력을 매번 읽으면 토큰만 늘고 환각을 부른다"). 요약이 레거시가 되지 않도록, 도메인 문서를 의미 있게 바꾼 뒤(= 개발·변경이 끝나면) **일지 항목 1개 추가 + 현재 상태 요약 갱신**을 하네스가 강제한다. 이 하네스는 `CLAUDE.snippet.md`를 대상 `CLAUDE.md`에 한 번 붙이면 켜진다.

## 실행
- `templates/CLAUDE.snippet.md`: 도메인 일지 하네스(쓰기 전용) — 의미 있는 변경 후 일지 1항목 추가 + `현재 상태 요약` 갱신을 강제.
- `docs/conventions.md` §일지 하네스: 요약(읽음) / 일지(쓰기 전용) 분리 규약, context-pack 전 티어에서 일지 제외.
- `b63d9db`: 기획 골격 템플릿 + 일지 하네스 스니펫 도입.
- `0ee6d63`: 수직 도메인 재편에 맞춰 규약·하네스 갱신.

## 결과
AI는 도메인에 들어올 때 항상 최신 `현재 상태 요약`(누적 학습)만 읽고 동작하며, 누적 이력은 검색·주입에서 제외되어 토큰·환각을 늘리지 않는다. 요약은 개발 종료 시 갱신이 강제되므로 레거시로 썩지 않는다. distill(작성 시점 요약) · 일지 write-only(읽기 시점 제외) · context-pack(검색 시점 골격화)의 3중 레이어로 맥락이 항상 얇게 유지된다.

## 회고
"AI가 쓴 문서를 AI에게 다시 안 읽힌다"가 반직관적이지만 핵심이었다. 맥락은 많이 주는 게 아니라 **항상 최신인 한 겹만** 주는 것이 옳다. 누적 이력을 격리하고 요약 갱신을 규약으로 강제하니, 사람이 매번 문서를 손보지 않아도 도메인이 스스로 최신 맥락을 유지한다.
