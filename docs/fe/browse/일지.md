# fe/browse 일지

## 현재 상태 요약
plan-fe + qa + 값 역채움 완료(build 게이트 정합). 3계층 플로우(랜딩→프로젝트인덱스→포인트상세) + 전역 FAB. 값 전부 충족 — 추천=featured 우선+최신순 상위3, 프로젝트 정렬=구현 기본(0-포인트 후순위), 없는/비공개 접근=랜딩 리다이렉트, 빈 상태=안내, 아키텍처=텍스트/마크다운, 부분 렌더=선택 섹션 생략. BE 호출 링크 = be/point·**be/project**(분리 전파). 남은 슬롯 없음(패턴은 FE라 해당 없음).

**v4 확장(plan-fe):** 두 렌더 경계만 손댐(새 화면·전이 없음). ① **포인트상세=visible-only** — 공개 DTO에 invidence(디테일·코드)가 실리지 않아 FE는 받지도 노출하지도 않음, 숨은 상세는 챗봇으로만 드러남(UX 계약). ② **프로젝트인덱스=압축 도식 임베드** — `architectureDiagram`(SVG) 있으면 아키텍처 개요 곁에 인라인, null이면 텍스트만(하위호환). 임베드·다크모드·배치 미세값은 구현. 참조 그래프 무변. (v4 두 문서 distill 완료 — 본문 슬림화, 근거는 일지로 흡수.)

## 이력
### 2026-06-27 — fe/browse 플로우·진입점 확정
- **결정:** 랜딩 = 상단 추천 포인트 + 하단 프로젝트 목록. 프로젝트 여러 개 전제 → 3계층 유지. 챗봇 진입점 = 전역 우하단 FAB(상시, v1). 인라인 텍스트 선택-질문은 v3로 연기.
- **왜:** 화면(FE)부터 구체화해 BE를 도출하는 FE-first 순서(→ Project_DDD #10). FAB는 업계 표준·구현 가벼움(리서치 근거). 인라인 선택-질문은 우리 근거기반 Q&A와 잘 맞으나 텍스트 선택 처리·모바일 UX 비용이 있어 뒤로.
- **영향:** be/point에 랜딩(추천·프로젝트 목록 조회)·인덱스(프로젝트 데이터)·상세(포인트 단건) 호출이 요구됨 → 다음 plan-be 입력. 로드맵에 인라인 선택-질문 v3 행 추가.

### 2026-07-12 — v4 렌더 경계 확장 (plan-fe)
- **결정:** ① 포폴-포인트-상세는 **visible만** 렌더 — invidence(사람 디테일 + 커밋 코드)는 공개 DTO에 없어 FE에 도달하지 않음. FE에 "숨김 토글"을 두지 않고, 숨은 상세는 챗봇 답변으로만 노출(be/chat 하이브리드 코퍼스). ② 프로젝트-인덱스는 `architectureDiagram`(be/project가 typst→SVG 컴파일해 반환) SVG를 아키텍처 개요 곁에 임베드, 없으면 텍스트만.
- **왜:** task-3(하이브리드 문서)은 "페이지=요약, 챗봇=디테일" 경계가 핵심 — FE가 invidence를 받지 않게 해 경계를 데이터 단에서 못박음(누출·실수 방지). task-2(도식)는 긴 architecture 텍스트를 한눈 도식으로 보완, optional이라 하위호환.
- **영향:** 새 도메인·전이·참조 엣지 없음(HOME v4 표대로). BE 계약 변화는 be/point(공개 DTO=visible 유지)·be/project(architectureDiagram 반환 추가)에서 이미 명세. FE 남은 슬롯은 구현 미세값(임베드 방식·다크모드 대비·배치)뿐 — 정책 슬롯 없음.

### 2026-07-12 — v4 렌더 경계 문서 distill (가지치기)
- **결정:** 포폴-포인트-상세·프로젝트-인덱스의 v4 인라인 문단을 가지치기. 포인트상세는 같은 규칙이 '로드하는 값'(visible만 수신)과 '화면·연출'(invidence 미노출)에 중복 → 로드=데이터 경계(무엇을 받나)·화면=렌더 결과(펼치기 UI 없음, 챗봇 전용)로 역할 분리해 각각 핵심만 남김. 프로젝트인덱스는 도식 임베드 문장의 배치 서술("곁/위")을 제거(같은 줄 "배치 미세값은 구현"과 중복).
- **왜(이송):** "FE는 숨기는 게 아니라 받지 않음 — 렌더 경계가 곧 데이터 경계" 근거는 본문에서 제거하고 상단 2026-07-12 v4 렌더 경계 항목으로 흡수(중복). distill 원칙 = 결정이력은 일지, 본문은 완결 문장만.
- **영향:** 계약·참조 무변, 본문만 슬림화. 두 문서 상단 요약에 각각 visible-only·도식 우선 한 줄 반영. 남은 슬롯 = 구현 미세값(임베드·다크모드·배치)뿐, 정책 슬롯 없음.

### 2026-06-29 — build 게이트 값 역채움 + be/project 분리 전파
- **결정:** 요소·플로우의 [입력 필요]를 plan-be·arch·티켓에서 확정된 값으로 역채움. 프로젝트 목록·인덱스 조회를 be/point→**be/project**로 정정(decompose 분리 전파). 추천=featured+최신순 상위3 / 정렬=구현 기본 / 접근 차단=랜딩 리다이렉트 / 아키텍처=텍스트/마크다운.
- **왜:** fe/browse만 qa 후 값 역채움을 안 거쳐 도메인 문서가 stale이었고, build(desk)가 도메인 폴더를 계약서로 쓰므로 슬롯을 닫아야 dispatch 가능.
- **영향:** fe/browse build-ready. BE 호출 링크가 실제 기능 문서를 가리킴.
