# pofol — 인터뷰로 근거기반 포트폴리오 저작

포트폴리오 항목(`wiki/<slug>/` = 표지 + 포인트 N개)을 **사람에게 캐물어(인터뷰) 저작**한다.
서사(문제·결정·회고)는 **사람의 답에서** 나오고, AI는 짓지 않고 **끌어내서 기록**한다.
대상 레포의 git 이력은 **질문 재료 + Evidence 근거**로 쓴다. 근거 없으면 발행 불가.
**모든 응답은 한글.** 로컬 Claude Code 저작(무과금 — 서빙 챗봇만 API).

## 절대 규칙 (값을 짓지 않는다 — 엘리시테이션)

- **서사는 사람에게서**: 문제·고려한 옵션·결정과 근거·회고는 **사람 답변**으로 채운다. AI가 대신 지어 쓰지 않는다. git·README는 *물어볼 거리와 근거*일 뿐 자동 서사가 아니다.
- **생각 극대화**: "왜?"에서 한 번에 멈추지 말고 대안·트레이드오프·근거까지 파고든다. 답이 얕거나 모호하면 구체값을 더 캐묻는다.
- **Evidence는 실재 커밋/PR만**: 사람이 결정을 말하면 "그걸 뒷받침하는 커밋/PR은?"을 묻고 git에서 후보를 제시해 고르게 한다. 해시·날짜는 git 확인분만(`git log --date=short`).
- **사람만 아는 값**(role·teamSize·period)은 묻는다. 안 주면 `[입력 필요]` 슬롯.

## 0. 입력

- **대상 레포**: 로컬 경로 또는 GitHub `owner/repo`(근거·질문 재료 소스). 불명확하면 묻는다.
- **인터뷰이 = 사용자.** slug=kebab, `wiki/<slug>/`가 항목 단위. 포인트 `project:` = slug 일치.
- **모드**: 기본 **인터뷰**(정식). 빠른 자리표시가 필요하면 **git 초안**(임시 — 부록 A), 나중에 인터뷰로 교체.

## 1. 참조 준비 (git = 질문 재료)

- GitHub면 스크래치패드에 클론(`gh repo clone <owner>/<repo> -- --depth 200`, gh 경로 `C:\Program Files\GitHub CLI\gh.exe`). 로컬이면 그 경로.
- README·매니페스트·`git log --oneline`으로 **ADR감 아크**(결정·리팩토링·재설계)를 추려 **"이거 왜 이렇게 했어요?" 질문 목록**을 만든다. 여기서 서사를 자동으로 쓰지 않는다.

## 2. 인터뷰 (핵심 — 섹션별 엘리시테이션)

표지 먼저, 그다음 포인트별로. **한 번에 하나씩** 캐묻는다:

- **표지**: 한줄요약·역할·기간·팀·기술스택·핵심성과 (사람 답 + git 확인).
- **포인트(9섹션)**: 무슨 **문제**였나 → 어떤 **옵션**을 고려했나(장·단·비용) → **왜 그걸** 택했나(트레이드오프 = 결정과 근거) → **실행/결과** → **회고**(배운 것).
  - 각 결정마다 **근거를 강제**: git 커밋/PR 후보를 제시 → 사람이 고르거나 확인.
  - 얕으면 더 판다: "그 대안은 왜 안 됐죠?" "그 수치의 근거는?" "그때 트레이드오프는?"

## 3. 기록 (be/point·be/project 형식)

사람 답을 그대로 형식에 옮긴다(AI가 살 붙여 지어내지 않는다).

- **표지** frontmatter: `name`·`summary`·`role`·`period`·`teamSize`·`techStack`·`architecture`·`highlights`.
- **포인트** H2 9섹션 그대로: `## 제목·요약 / 배경 / 문제 / 고려한 옵션`(표)`/ 결정과 근거 / 실행 / 결과 / 회고 / Evidence`(표). frontmatter `id`·`title`·`project`·`status: draft`·`tags`·`commits`·`updated`.
- **문구 압축**: `summary`·`title`은 핵심 한 문장/짧게(콤마 나열 금지). **콜론 들어간 title은 따옴표**(`title: "…: …"` — 안 그러면 YAML 깨짐). `featured`는 **대표작 2~3개만**(남발 금지).
- 옵션 표 `옵션 | 장점 | 단점 | 채택`(O/X, 대안 있었으면 꼭). Evidence 표 `종류 | 라벨 | 링크`(commit/pull URL).

## 4. 발행 게이트

포인트마다 `backend/.venv/Scripts/python.exe scripts/publish.py <id>`. 게이트 = title + 요약(1) + 문제(3) + 결정과 근거(5) + Evidence≥1(9). 미충족이면 그 부분을 **다시 인터뷰**해 보강한 뒤 재시도.

## 5. 미리보기·보고

- `/setting`으로 서버가 떠 있으면 브라우저(localhost:3000)에서 바로 확인(BE는 요청마다 위키를 읽어 재기동 불필요).
- `[입력 필요]` 잔여·다음 포인트 제안을 보고. **커밋은 사용자가 요청할 때만**, push 안 함.

## 부록 A. git 초안 모드 (임시 자리표시)

인터뷰 전 빠른 뼈대가 필요하면: git 이력의 ADR감 아크에서 draft 포인트를 **자동 초안**한다(커밋 본문에서 도출, Evidence는 실재 커밋만). **이 콘텐츠는 임시다** — 반드시 §2 인터뷰로 내부 내용을 사람 답변으로 교체한다.
