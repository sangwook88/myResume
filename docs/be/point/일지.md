# be/point 일지

## 현재 상태 요약
fe/browse qa 매핑표에서 도출한 골격 + 사람 값 확정 완료(plan-be). 데이터(포폴포인트 frontmatter+9섹션 본문+Evidence 5종) + 기능 3개(추천목록·프로젝트별목록·단건조회). 비즈니스 값 전부 충족 — 추천=featured 우선+동점 최신순 상위3, 정렬=구현 기본, 발행=별도 명령(Evidence≥1+핵심섹션 1·3·5·9 검증), 비공개/없는 항목=랜딩 리다이렉트, 포맷=케밥/ISO/git range. v1 패턴=TS 확정, 구현·검증 완료.

**v4 확장(plan-be→distill 완료):** Evidence 밑 **invidence 숨은 층**(detail=사람 인터뷰 저작 / code=발행 시 커밋 추출) 신설 + 기능 2개(챗봇컨텍스트조회=be/chat 전용 visible+invidence 합집합 / 발행코드추출=발행 시 1회 git 추출). 공개 조회 3개는 invidence 제외 유지. **값 확정(사람):** 저장 위치=detail 문서 내 숨은 섹션·code 사이드카 파일 / 추출 단위=변경 hunk만 / 대상 kind=commit·pr(ref=Evidence url 해시). v4 문서 3개 distill 가지침(공개/비공개 분리 규칙 3중 반복 통합) 완료. **남은 슬롯 전부 사람 확정(plan-be):** detail=상한 없음·숨은 섹션 `## 챗봇전용 [[E##]]` / code 사이드카=`wiki/<project>/<id>.code.md` / code 상한 초과=앞부분 자름+`…(잘림)`(상한 값은 구현 튜닝) / ref 실패=code 비우고 발행 / 재발행 code=덮어쓰기 / 발행 게이트 영향=없음. **잔여 슬롯 0(정책).** **arch 완료(ARCHITECTURE §v4-A):** detail=숨은 섹션 `## 챗봇전용 [[E##]]`·code=사이드카 `.code.md`, 공개 조회는 미포함·be/chat만 챗봇컨텍스트조회로 합집합, 발행코드추출=빌드타임 git 유틸. 패턴 TS. → 다음 ticket.

## 이력
### 2026-07-12 — v4 invidence 구조 확정 (arch)
- **결정:** 스택 무변(git-md 파싱 TS) + 파싱 2종만 추가 — detail=포인트 문서 내 숨은 섹션 `## 챗봇전용 [[E##]]`(공개 파서 무시), code=사이드카 `wiki/<project>/<id>.code.md`. 접근 경로 물리 분리: 공개 조회 3함수는 invidence 미포함, be/chat만 챗봇컨텍스트조회(visible+invidence 합집합)로 읽음. 발행코드추출=`scripts/publish.py` 빌드타임 유틸(commit·pr ref→git hunk 1회 추출, 재발행 덮어씀, ref 실패=비우고 진행). 서빙 시 git 무접근.
- **왜:** invidence는 발행-시점 고정이라 챗봇 캐시 프리픽스(코퍼스)의 일부로 자연 편입 — 서빙 런타임 git 접근 없이 캐싱·단순성 유지. 새 도메인·의존 없음(be/point 안 흡수).
- **영향:** ARCHITECTURE §v4-A 기입. 패턴 무변(TS, README 슬롯 그대로). 미결=code 크기 상한 수치값(구현 튜닝, dev).

### 2026-07-12 — v4 invidence 잔여 슬롯 값 확정 (plan-be)
- **결정(사람):** detail 길이=명시 상한 없음(자유 텍스트) / detail 저장=포인트 문서 내 숨은 섹션, Evidence 토큰별 `## 챗봇전용 [[E##]]` 블록 / code 사이드카=`wiki/<project>/<id>.code.md` / code 크기 상한 초과=앞부분 자름 + `…(잘림)` 표시(상한 값 자체는 구현 튜닝) / ref 해석 실패=code 비우고 발행 진행(발행 막지 않음, git 미설치 처리와 동일) / 재발행 code=덮어쓰기(재추출로 사이드카 교체, 버전 누적 안 함) / 발행 게이트 영향=없음(invidence 없어도 발행, Evidence≥1 불변).
- **왜:** 코드 공급은 챗봇 맥락 보강이 목적이라 발행을 막지 않는 쪽으로 통일(자름·비우고 진행·게이트 무영향) → 발행 안정성 우선. 사이드카·숨은 섹션 경로는 포크 셀프호스팅 git-md 규약 계승.
- **영향:** be/point v4 정책 슬롯 0. 다음 = arch로 패턴·구조(사이드카 파싱·발행 스크립트 배치) 결정 후 dev.

### 2026-06-29 — be/point 신설 (FE-first 도출)
- **결정:** decompose에서 프로젝트 표지를 be/project로 분리(SRP) → be/point는 개별 포폴 포인트(2계층)만 소유. fe/browse qa가 부르는 호출(추천목록·프로젝트별목록·단건)에서 기능 3개 도출, 데이터는 목차-설계 §5·§7 frontmatter+9섹션+Evidence로 역산.
- **왜:** 포인트와 프로젝트 표지는 각자 다른 데이터를 소유 → 단일 소유 규칙·세분할 granularity.
- **영향:** be/point는 말단(sink, depends 없음). be/project·be/chat이 be/point를 단방향 참조.

### 2026-06-29 — 값 확정 (사람 결정)
- **결정:** 추천=`featured` 태그 우선+동점 `updated` 최신순 상위 3 / 목록 정렬=구현 기본(임의) / 발행=별도 명령으로 draft→published, 게이트 검증=Evidence≥1+핵심 섹션(1·3·5·9) / 비공개·없는 id=랜딩 리다이렉트 / 부분 렌더=선택 섹션 비면 생략 / Evidence kind=commit·pr·swagger·file·link / 포맷=id·slug 케밥, updated ISO, commits git range.
- **왜:** 개인 포폴·로컬 구독 저작 모델이라 큐레이션·경량 게이트가 적합. 근거 강제(Evidence≥1)는 제품 차별점.
- **영향:** be/point 비즈니스 슬롯 전부 충족. 남은 건 arch의 패턴(TS/DM)뿐 → distill 가능.

### 2026-06-29 — arch 패턴 확정: TS
- **결정:** 패턴 = 트랜잭션 스크립트(TS). 스택 = Python/FastAPI, 콘텐츠는 git 마크다운을 Python이 파싱해 API 서빙.
- **왜:** 파일 파싱→DTO 조회 + 발행 게이트 검증은 얇은 절차적 규칙이라 도메인 모델 과설계.

### 2026-06-29 — distill 가지치기
- **결정:** Evidence kind 표 셀의 stale 표기(3종→enum 5종 참조)로 정제, 추천 입력의 자명한 메타 1줄 삭제, 단건조회 리다이렉트 중복(처리·예외)을 예외 1곳으로 통합.
- **왜:** 핵심 의미 보존하며 군더더기·중복·불일치 제거(slim-agent).
- **영향:** 의미 불변. be/project 문서는 이미 완결이라 변경 없음.

### 2026-07-12 — v4 invidence 확장 (plan-be)
- **결정:** Evidence를 별도 be/evidence 도메인으로 떼지 않고 be/point 안 **Evidence 종속 숨은 층(invidence)** 으로 흡수. detail(사람)·code(기계 발행 시 추출) 2필드. 공개 조회 3함수는 invidence 미포함, be/chat 전용 접근자(챗봇컨텍스트조회)만 노출 → 공개/비공개 경로 물리 분리. git-읽기(발행코드추출)는 발행 플로우 얇은 유틸(런타임 아님).
- **왜:** 코드가 그 근거 커밋에서 자연히 따라오고 디테일도 관련 근거 밑에 붙음(같은 파일·같은 발행 게이트 공유) → 도메인 안 늘림. 서빙 시 git 무접근으로 캐싱(4번)·단순성 유지. (HOME v4 섹션·roadmap v4)
- **영향:** 참조 그래프 무변(invidence는 be/point 문서에 실려 be/chat→be/point가 커버). 값 슬롯은 사람 확정 대기(distill 전).

### 2026-07-12 — v4 문서 distill 가지치기 (데이터·챗봇컨텍스트조회·발행코드추출)
- **결정:** "공개 조회와 물리 분리·invidence 미노출" 규칙이 데이터.md(intro/공개-비공개 bullet)·챗봇컨텍스트조회(intro/처리/예외) 등에 3중 반복 → 각 문서 intro 한 곳으로 통합. code 값칸의 "변경 hunk만" 중복·intro의 "마크다운 파싱 규칙=[입력 필요]"(저장 위치 슬롯과 겹침) 제거. 발행코드추출 "포크 셀프호스팅이라 로컬 git" 근거절 축약, 실패 처리(확정 git-실패 / 슬롯 ref-실패) 정렬 정제.
- **왜:** slim-agent — 핵심 의미(트리거·합집합·published-only·저장 위치·추출 단위) 보존하며 반복·자명절 제거. 결정이력은 위 v4 항목이 커버.
- **영향:** 의미 불변. 미충족 슬롯(코드 크기 상한·사이드카 경로·숨은 섹션 형식·detail 상한·재발행·ref 실패·발행 게이트 영향) 전부 [입력 필요]로 보존.
