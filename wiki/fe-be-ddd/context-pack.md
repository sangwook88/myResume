## 제목·요약
에이전트가 문제를 풀 때 레포 전체를 헤매지 않고, **책임이 있는 도메인(데이터·규칙을 소유한 곳)에 바로 도달**한다. 그 도메인과 참조로 닿는 이웃의 **코드·참조를 이름(시그니처)만 긁어 골격으로 요약**해 한눈에 주입하므로, "어디에 어떤 책임 코드가 있고, 없으면 뭘 만들어야 하는지"를 즉시 판단해 곧장 고친다. `/ticket` 스킬이 이 흐름을 콜드 스타트가 티켓 한 장만 읽고 구현 가능한 자기완결 티켓으로 구현한다.

## 배경
이 프레임워크는 구현·분석을 콜드 스타트 서브에이전트에 맡긴다(컨텍스트 오염 차단). 콜드 스타트는 대상 도메인과 그 의존을 모른 채 시작하므로, "무엇을 얼마나 넣어주느냐"가 정답률과 토큰 비용을 동시에 좌우한다.

## 문제
처음엔 프로젝트 전체 클래스 구조 맵(repomap식)을 만들었다. 그런데 클래스 참조 구조가 뒤죽박죽이라, 전체 맵이 있어도 "이 값 참조가 어디서 오나"를 못 찾아 헤맸다 — 고칠 건 A 폴더의 클래스 한 줄인데 그걸 못 찾아 새로 짜버리거나, 확인하려고 쓸데없는 데까지 뒤지다 삼천포로 빠졌다. 전체를 다 넣으면 토큰이 폭발하고, 적게 넣으면 이웃 도메인의 계약(호출 대상)을 몰라 헛짚는다. 지도의 문제가 아니라 **참조를 코드 추론에 맡긴 것**이 문제였다.

## 고려한 옵션
| 옵션 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 대상 도메인 문서만 통째로 | 단순 | 이웃 계약 미인지 → 호출을 헛짚음 | X |
| 전체 위키 load-all | 누락 없음 | 토큰 폭발 / 대규모에서 불가 | X |
| repomap식 코드 추론 (tree-sitter + PageRank) | 언어 불문 자동 | 참조를 매번 추론 → 뒤엉킨 코드에선 부정확·비쌈 | X |
| 선언된 도메인 그래프 + 거리 티어 골격 | 참조가 선언(단일 소스)이라 결정적 / 관련도에 비례한 압축 | 그래프 규약을 사람이 유지 | O |

## 결정과 근거
참조를 코드에서 추론하지 않고 **`HOME.md` 참조 그래프에 선언**해 단일 소스로 못 박았다(FE→BE·BE→BE, 단방향·비순환). 도메인 경계가 폴더 1개=노드 1개로 이미 분리돼 있으니, repomap이 tree-sitter+PageRank로 어렵게 *추정*하는 의존·중심성이 우리에겐 **결정적**이다(추정 아님). 그 위에서 그래프를 BFS로 순회해 거리별 티어(T0=대상 전문 / T1=직접 이웃의 계약면만 / T2+=한 줄 역할)로 압축하고, 코드는 시그니처만 골격화(본문 생략)해 붙인다. "선언은 신뢰하고 코드는 추론한다"로 역할을 분리 — 그래프는 사람이 관리하는 단일 소스, 코드 골격은 기계가 뽑는 현실.

## 실행
- `scripts/context-pack.mjs`: HOME BFS로 T0/T1/T2 압축, `--with-code`로 타깃 T0에 코드 골격 append.
- `scripts/code-map.mjs`: 코드에서 시그니처 골격 추출(본문은 ⋮로 생략). ctags(정밀·다언어) → 정규식(언어 불문) 2단 폴백.
- `scripts/home-check.mjs`: 선언 그래프(HOME) ↔ 현실(depends:/링크) 정합성 + 코드 폴더 존재 + 순환 탐지(CI 게이트).
- `/ticket` 스킬: 책임 도메인 분류(데이터·규칙 소유자)로 도달점을 정하고, 자기완결 티켓 1장에 변경 파일·시그니처를 못 박아 콜드 엔진에 넘긴다.
- `16adc3c`: dev 구현 시작 컨텍스트를 context-pack으로 배선(Phase 3).

## 결과
디스패치 전 컨텍스트가 그래프 거리에 비례해 자동 구성되어, 콜드 스타트 서브에이전트가 이웃 도메인의 계약을 인지한 채 시작한다. 티켓 한 장만 읽고 "어디를 어떻게"를 바로 구현한다. ctags가 없는 환경에서도 정규식 폴백으로 언어 불문 골격 추출이 되어 이식성을 확보했다.

## 회고
repomap의 세 요소(의존 그래프·중요도 랭킹·예산 골격화) 중 앞 둘을 **선언으로 공짜로 확보**한 게 핵심이었다. 코드가 뒤엉킬수록 추론(tree-sitter)은 부정확해지지만, 참조를 사람이 선언해 두면 정합성 검증(home-check)과 압축(context-pack)이 같은 단일 소스 위에서 결정적으로 돈다. 인덱스가 없으니 staleness도 없다 — Claude Code가 벡터 인덱스를 버리고 agentic search를 택한 것과 같은 선택이다.
