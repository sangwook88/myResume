# pofol — git 초안 + 인터뷰로 근거기반 포트폴리오 저작

포트폴리오 항목(`wiki/<slug>/` = 표지 + 포인트 N개)을 **2단계**로 만든다:

- **1단계 (AI · git)**: git 이력에서 **사실**을 뽑아 뼈대를 초안한다 — 무엇을 했나·실행·근거 커밋(Evidence).
- **2단계 (사람 · 인터뷰)**: git이 모르는 **판단**을 대화로 채운다 — 당시 생각·기술 트레이드오프·왜 그 결정·결과·회고.

**git = "무엇을"(사실, 검증 가능) / 사람 = "왜·어떻게·배운 것"(판단, git엔 없음).**
AI는 판단을 지어내지 않고 사람에게서 끌어낸다. 로컬 Claude Code 저작(무과금 — 서빙 챗봇만 API). 모든 응답 한글.

## 절대 규칙
- **판단은 사람에게서**: 문제 인식·옵션 트레이드오프·결정 근거·회고는 **사람 답변**으로 채운다. git 커밋에서 유추한 서사는 `[확인 필요]` 잠정일 뿐 — 사람이 확정/교체하기 전엔 **발행하지 않는다**.
- **Evidence는 실재 커밋/PR만**: 해시·PR·날짜는 git 확인분(`git log --date=short`)만. 추측 금지.
- **사람만 아는 값**(role·teamSize·period)은 묻는다. 안 주면 `[입력 필요]`.

## 0. 입력
- **대상 레포**: 로컬 경로 또는 GitHub `owner/repo`. 불명확하면 묻는다.
- slug=kebab, `wiki/<slug>/`가 항목 단위. 포인트 `project:` = slug 일치.

## 1단계 — git 분석 → 사실 뼈대 초안 (AI)
- GitHub면 스크래치패드에 클론(`gh repo clone <owner>/<repo> -- --depth 200`, gh 경로 `C:\Program Files\GitHub CLI\gh.exe`). 로컬이면 그 경로.
- README·매니페스트·`git log --oneline`으로 **ADR감 아크**(결정·리팩토링·재설계)를 뽑아 포인트 후보로.
- 각 포인트 초안:
  - **사실 채움**(git 근거): `## 제목·요약`(무엇을) · `## 실행`(커밋들이 한 일) · `## Evidence`(커밋/PR 링크) · `## 배경`(사실 부분).
  - **잠정 채움 + `[확인 필요]`**: `## 문제` · `## 고려한 옵션` · `## 결정과 근거` · `## 결과` · `## 회고` 는 커밋 본문에서 유추해 쓰되 반드시 **`[확인 필요]`** 를 붙인다(2단계에서 교체 대상).
- 표지: 사실(name·techStack·period·architecture)은 초안, role·teamSize는 `[입력 필요]`.

## 2단계 — 인터뷰 → 판단 채움 (사람)
포인트별로 `[확인 필요]` 섹션을 **한 번에 하나씩** 대화로 채운다:
- **문제**: 그때 뭐가 진짜 문제였어요? 왜 중요했죠?
- **고려한 옵션·트레이드오프**: 어떤 대안들을 놓고 고민했어요? 각각 장·단·비용은? (옵션 표 채움)
- **결정과 근거**: 왜 그걸 택했어요? 무엇을 포기(트레이드오프)했죠? → 뒷받침 커밋 확인.
- **결과·회고**: 결과가 어땠어요? 지금 보면 뭘 배웠거나 다르게 할까요?
- 얕으면 더 판다("그 대안은 왜 안 됐죠?" "그 수치의 근거는?"). 사람 답으로 잠정 서사를 **교체**하고 `[확인 필요]`를 지운다.

## 3. 형식 (be/point·be/project 계약)
- **H2 9섹션 그대로**: `## 제목·요약 / 배경 / 문제 / 고려한 옵션`(표)`/ 결정과 근거 / 실행 / 결과 / 회고 / Evidence`(표).
- 표지 frontmatter: `name`·`summary`·`role`·`period`·`teamSize`·`techStack`·`architecture`·`highlights`. 포인트 frontmatter: `id`·`title`·`project`·`status: draft`·`tags`·`commits`·`updated`.
- **문구 압축**: `summary`·`title`은 핵심 한 문장/짧게(콤마 나열 금지). **콜론 title은 따옴표**(`title: "…: …"`, 안 그러면 YAML 깨짐). `featured`는 **대표작 2~3개만**.
- 옵션 표 `옵션 | 장점 | 단점 | 채택`(O/X). Evidence 표 `종류 | 라벨 | 링크`(commit/pull URL).

## 4. 발행 게이트
**`[확인 필요]`가 남은 포인트는 발행하지 않는다**(판단 미확정). 다 채워졌으면 `backend/.venv/Scripts/python.exe scripts/publish.py <id>`. 게이트 = title + 요약(1) + 문제(3) + 결정과 근거(5) + Evidence≥1(9). 미충족이면 그 부분을 다시 인터뷰해 보강.

## 5. 미리보기·보고
- `/setting` 떠 있으면 브라우저(localhost:3000)에서 바로 확인(BE는 요청마다 위키를 읽음).
- `[확인 필요]`(인터뷰 대기)·`[입력 필요]`(role 등) 잔여를 보고. **커밋은 사용자 요청 시만**, push 안 함.
