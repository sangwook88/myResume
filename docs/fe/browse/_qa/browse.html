[예시] 결제 멱등성 키로 중복 청구 0건 달성

결제신뢰성멱등성

[예시] 네트워크 재시도로 인한 중복 결제를 멱등성 키 설계로 차단해 청구 분쟁을 제거한 결정.

배경

[예시] 결제 승인 API가 클라이언트 재시도 시 동일 요청을 두 번 처리, 월 평균 12건 중복 청구 분쟁 발생.

문제

[예시] 동일 결제 의도를 한 번만 반영해야 하나, 분산 환경에서 요청 단위 중복 제거 기준이 없었다.

고려한 옵션
옵션장점단점비용/리스크채택
[예시] DB 유니크 제약만단순재시도 응답 불명확낮음
[예시] 멱등성 키 + 결과 캐시재시도 안전·응답 일관키 저장소 필요중간●
[예시] 분산 락강한 직렬화지연·복잡도 증가높음
결정과 근거

[예시] 멱등성 키(Idempotency-Key) + Redis 결과 캐시 채택. 재시도 시 캐시된 응답을 그대로 반환해 부작용 없는 멱등을 보장.

실행

[예시] 결제 진입점에 키 미들웨어 도입, 24h TTL 결과 저장, 키 충돌 시 409 반환. 단계적 롤아웃.

결과
  • [예시] 중복 청구 분쟁 월 12건 → 0건
  • [예시] 재시도 응답 일관성 100%
회고

[예시] 키 생성 책임을 클라이언트에 둔 점이 초기 혼선. 다음엔 SDK 차원 기본 제공 고려.
