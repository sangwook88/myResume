# 요소: 포폴-포인트-상세

*포폴 포인트 1개를 9섹션(STAR+ADR)으로 렌더하고, Evidence(근거 링크)를 클릭-검증 가능하게 노출한다. 공개 visible 층만 렌더 — 숨은 상세(invidence)는 챗봇 몫. 이 도메인의 핵심 화면.*

## 진입·트리거
- 랜딩의 추천 포인트 선택, 또는 프로젝트인덱스의 포인트 목록 선택.

## 로드하는 값 (입력)
- 보장: 포폴 포인트 `id`(+ 소속 `project`).
- 읽는 값: 해당 포인트의 9섹션 본문 + 프론트매터(title·tags·commits 등) + Evidence(커밋/PR/Swagger 링크).
  - 9섹션: 제목·요약 / 배경 / 문제 / 고려한 옵션(표) / 결정과 근거 / 실행 / 결과 / 회고 / Evidence (근거: [포폴-목차-설계.md §5](../../../포폴-목차-설계.md))
- `status: published`만 노출. draft 직접 URL 접근 시 랜딩으로 리다이렉트(draft 존재 노출 안 함).
- **v4 — visible만 수신**: 단건 조회는 공개 DTO(visible 9섹션 + Evidence)만 반환. Evidence 밑 `invidence`(사람 디테일·일화 + 커밋 코드)는 공개 DTO에 없어 이 화면에 도달하지 않는다(챗봇 전용 컨텍스트).

## 호출하는 기능
- 포폴 포인트 단건 조회(`id` 기준, published 한정) → [be/point 기능_포인트단건조회](../../../be/point/기능_포인트단건조회.md)

## 분기·다음 전이
- **Evidence 항목 클릭** → 외부 근거 URL 새 탭 이탈(앱 밖)
- **같은 프로젝트 내 다른 포인트 선택** → 포폴-포인트-상세 (재진입)
- **뒤로** → 프로젝트인덱스
- **전역 FAB 클릭** → [fe/chat](../../chat/) 진입 (**현재 포인트 `id`를 맥락으로 전달**)
- 인라인 텍스트 선택-질문은 **v3** — v1 미포함.

## 내보내는 값 (출력)
- 외부근거로: Evidence 외부 URL
- (재진입) 포인트상세로: 다른 포인트 `id`

## 예외·실패 처리
- 존재하지 않는/비공개 `id`: 랜딩으로 리다이렉트.
- Evidence 결손: 발행 게이트가 Evidence ≥1을 강제하므로 published에는 결손이 없다(별도 표기 불필요).
- 부분 렌더: 핵심 섹션(제목·요약/문제/결정과 근거/Evidence)은 발행 게이트로 보장. 선택 섹션(배경·실행·결과·회고·옵션표)이 비면 해당 섹션 생략 렌더.

## 화면·연출 (V)
- 9섹션 렌더. 옵션 비교는 고정 컬럼 표(옵션·장점·단점·비용/리스크·채택).
- **v4 — invidence 미노출**: invidence를 펼치는 UI는 두지 않는다 — 숨은 상세는 챗봇 답변으로만 드러난다(be/chat 하이브리드 코퍼스; "물어보면 챗봇이 안다"가 UX 계약).
- Evidence 링크는 클릭-검증 가능하게(외부 새 탭). 고급 Evidence UI(각주/펜첼형)는 v2 — v1은 기본 링크.
- 우하단 전역 FAB 상시 표시.
