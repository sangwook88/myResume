# be/project 일지

## 현재 상태 요약
decompose에서 be/point로부터 SRP 분리되어 신설(plan-be) + 사람 값 확정 완료. 데이터(프로젝트 index 표지 §4의 1~5) + 기능 2개(프로젝트목록조회·프로젝트인덱스조회). 포인트 목록은 저장 않고 be/point에서 파생 조립(§7.3). 비즈니스 값 전부 충족 — 정렬=구현 기본, 0-포인트 프로젝트=노출하되 후순위+포인트슬롯 숨김, 아키텍처=텍스트/마크다운, 없는 slug=랜딩 리다이렉트, 포맷=케밥 slug·`YYYY.MM–`. 남은 슬롯은 패턴(TS/DM, arch)뿐.

## 이력
### 2026-06-29 — be/project 신설 (decompose SRP 분리 + FE-first 도출)
- **결정:** fe/browse qa가 드러낸 프로젝트인덱스 화면의 표지 데이터를 근거로, 프로젝트 표지(1계층)를 be/point에서 분리해 별도 도메인으로 소유. 기능은 fe/browse 랜딩(프로젝트목록)·프로젝트인덱스(표지+포인트목록)에서 도출.
- **왜:** 프로젝트 표지(요약·역할·스택·아키텍처·성과)는 개별 포인트와 다른 데이터를 소유 → SRP·세분할 granularity(반사적 merge 금지).
- **영향:** 참조 그래프에 fe/browse→be/project, be/project→be/point(포인트목록 조립), be/chat→be/project, grill-me→be/project 추가. be/point는 말단 유지.

### 2026-06-29 — 값 확정 (사람 결정)
- **결정:** 프로젝트 정렬=구현 기본(임의) / published 포인트 0개 프로젝트=노출하되 카탈로그 후순위 + 인덱스 포인트목록 슬롯 숨김 / 아키텍처 개요=텍스트·마크다운(다이어그램은 뒤 버전) / 없는·노출불가 slug=랜딩 리다이렉트 / 표지 필드 자유 문자열, slug 케밥, period `YYYY.MM–`.
- **왜:** 개인 포폴 v1은 가볍게 — 표지는 채워 보여주되 빈 포인트는 숨겨 빈 화면 방지.
- **영향:** be/project 비즈니스 슬롯 전부 충족. 남은 건 arch 패턴(TS/DM)뿐.
