## v1 — 직접 쓴 근거 포폴 + load-all 챗봇 (MVP)
- **목표(가치)**: 개발자가 보여주고 싶은 프로젝트 내용을 **직접 작성**(근거 문서 강제 기재)해 메인 페이지에 렌더하고, 채용자가 둘러보다 챗봇으로 물으면 **그 내용 안에서 근거와 함께** 답한다. "근거 없이는 못 쓴다"는 강제 규칙으로 차별점(신뢰)을 증명.
- **포함 기능**:
  - 양식: 포폴 포인트 데이터 모델/템플릿(STAR+ADR + 근거 필수 필드)
  - 작성: 수동 작성(직접 작성 + 근거 강제 기재) + 발행 토글(draft→published)
  - 표현: 채용자 둘러보기 화면 + 디자인 템플릿 + Evidence 기본(근거 링크 클릭-검증)
  - 서빙: 챗봇 응답 엔진(load-all + 근거 링크 인용) + 챗봇 UI
- **제외(다음으로)**: 모드 토글·Evidence 고급 UI·둘러보기 고급화(→v2); 자동 git 분석·raw 인박스·Wiki 저작 엔진·RAG·자동 트리거(→v3)
- **전제(의존)**: 없음(MVP).

## v2 — 채용자 경험 심화
- **목표**: v1 핵심 루프 위에 채용자 경험을 다듬는다 — 적응형 눈높이, 근거를 깔끔히 보이기.
- **포함**: 모드 토글(기술/HR), Evidence 고급 UI(각주/펜첼형), 하이브리드 둘러보기 고급화.
- **전제**: v1의 챗봇 응답 엔진·둘러보기·Evidence 기본.

## v3 — 인라인 선택-질문  *(프로토타입 범위로 종료)*
- **구현 완료**: 챗봇 인라인 선택-질문(본문 드래그 선택 → "이 부분 물어보기" → 챗봇 자동 질문). `frontend/components/SelectionAsk.tsx`.
- **폐기(안 함으로 이동)**: 자동 git 분석 Source Agent, raw 범용 인박스, Wiki 저작·갱신 엔진, 검색/서빙 RAG, 자동 파일-드랍 트리거. 초기엔 v3 "자동화·규모 확장"으로 묶여 게이트 보류였으나, 2026-07-13 방향 피벗으로 **안 함(YAGNI)** 확정. `pofol` 로컬 저작이 저작 니즈를 대체 → 「안 함」 참조.
- **전제**: v1의 포폴 포인트 양식·챗봇·렌더.

## v4 — 콘텐츠 하이브리드 모델 + 도식 + 챗봇 정확도  *(완료, 2026-07-13)*
- **목표(가치)**: 포폴 내용을 **사람이 읽기 좋게**(AI 프로즈 대신 목차 스캐폴딩 위에 사람이 인터뷰로 직접 씀) 만들고, 챗봇은 페이지에 안 보이는 상세·코드까지 읽어 **더 정확히** 답한다. 텍스트뿐이던 아키텍처를 한눈 도식으로 보인다.
- **포함 기능**:
  - 콘텐츠: 하이브리드 단일 문서(목차 스캐폴딩 + 사람 인터뷰 저작 + 페이지-숨김 상세 + 코드 내용) — **항목 1·3 통합**, be/point 스키마 확장
  - 서빙: 챗봇 하이브리드 코퍼스(visible+hidden+code 합집합) + 코드 내용 공급(발행 시 Evidence 커밋 diff 1회 추출)
  - 표현: typst→SVG 압축 아키텍처 도식(프로젝트 페이지 임베드) — **항목 2**
  - 인프라: 프롬프트 캐싱·랭체인 정상화(프리픽스 고정·tone 후치·재배치 제거·1h TTL·실측) — **항목 4**
- **제외(안 함으로 확정)**: 자동 소스 인제스트(raw 인박스), 전체 2-Pass git 분석 Source Agent, 검색/서빙 RAG, watcher — 2026-07-13 피벗으로 **안 함(YAGNI)**. 단 **코드 공급은 v4에 이미 반영**(발행 시 Evidence 커밋 diff 1회 추출 = invidence 숨은 층). 별도 `be/git` 도메인은 만들지 않고 be/point의 invidence 하위 층으로 흡수함.
- **전제(의존)**: v1 be/point 양식·be/chat 응답 엔진·be/project 표지·fe/browse 렌더 위에 확장. 하이브리드 코퍼스는 콘텐츠 모델의 숨은/코드 필드에 의존(뒤가 앞을 깨지 않음).
- **착수 순서(권장)**: 독립적이고 챗봇 품질에 바로 꽂히는 **캐싱 정상화** 먼저 → typst 도식 → 콘텐츠 하이브리드 스키마 → 하이브리드 코퍼스·코드 공급.

## 다음 — 콘텐츠 채우기 페이즈 *(비-기능, 현재)*
- **목표**: 기능은 v4로 완성됐으므로, 담긴 내용을 실제로 만든다. 현재 wiki 는 git-마이닝 임시 데이터셋 → `pofol` 인터뷰로 실제 프로젝트 표지·포폴 포인트를 저작해 교체(근거 강제 기재).
- **성격**: 새 기능 버전이 아니다 — decompose/plan/ticket 을 돌리지 않는다. 저작 도구(`pofol`)를 써서 콘텐츠를 채우는 작업.
- **v5 판단**: 콘텐츠를 채우며 실제로 부족한 게 드러나면(예: 특정 UX·표현·챗봇 동작), 그때 v5 슬롯을 사람이 확정한다. 지금은 못 박지 않는다.

## 안 함 (YAGNI)
- **자동 git 분석 Source Agent (2-Pass + 증분)** — `pofol` 로컬 인터뷰 저작이 대체. 자동 소스가 실제로 필요해지면 그때 신규 기획.
- **raw 범용 인박스 + 추가 Source Agents** — 자동 소스 인제스트 니즈 없음(사람이 직접 저작).
- **Wiki 저작·갱신 엔진 (raw→wiki LLM 자동저작)** — AI 프로즈를 사람 인터뷰 저작으로 대체(v4 방향)했으므로 폐기.
- **검색/서빙 RAG (임베딩·벡터·리랭커)** — load-all + 프롬프트 캐싱으로 충분. 코퍼스가 ~50K 토큰 초과(Context Rot)해질 때에만 재검토.
- **자동 파일-드랍 트리거 (watcher)** — 외부 watcher 복잡 + 자동 소스 자체를 안 함.
- **음성/아바타 멀티모달** — 핵심(근거 기반 Q&A)과 무관.
- **다중 개발자 / 공개 SaaS** — 비전은 본인 1명 포폴. 서비스화는 제품-시장 검증 후에나.
